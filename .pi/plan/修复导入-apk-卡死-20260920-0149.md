# 修复导入 APK 卡死（版本号不变）

## 原因

上一版已经能“认出 APK”，但认法本身会把界面卡死。

`detectBookImportFormat()` 在文件名没有 `.apk` 时，只要文件头是 ZIP（`PK\x03\x04`），就会走 `_formatFromZip()` → `ZipDecoder().decodeStream()`。`archive` 4.0.9 对 **每一条 ZIP 记录** 都会 `readBytes(compressedSize)`，把压缩数据整段落进内存。APK 是带数千条目、`lib/*.so`、`classes.dex` 的 ZIP（本应用正式包约 54MB）。这段逻辑跑在 **UI isolate** 上，表现为导入后无响应。

系统选择器（SAF）经常丢掉后缀，缓存路径也可能是 `unamed`，所以即使用户选的是 `.apk`，仍会走到整包解码。文件名已是 `.apk` 时会立刻抛 `这是 Android 安装包，不是书籍`，这条路径本身不卡；卡死发生在“当 ZIP 去嗅探”的路径。

`file_picker` 的整文件拷贝在 `Dispatchers.IO` 上，不是这次 ANR 的主因。不换 `file_picker` 11.x。

## 行为

- 选中 APK（有无后缀、安装包 MIME、ZIP 内 `AndroidManifest.xml` + `classes.dex`）：很快 toast「这是 Android 安装包，不是书籍」，界面可点。
- TXT / EPUB / MOBI / PDF / DOCX / DOC 导入不变。
- `pubspec.yaml` 保持 `0.6.24+70`，不改公开版本和构建号。

## 改动

### 1. ZIP 只读中央目录，禁止用 ZipDecoder 嗅探

文件：`lib/services/book_import_format.dart`

- 用 `RandomAccessFile` / 已有 bytes 从文件尾找 EOCD（及常见 ZIP64），**只读中央目录里的文件名**。
- 上限：中央目录约 2MB、条目约 4096，避免畸形 ZIP 扫整文件。
- 判定：
  - APK：`AndroidManifest.xml` + `classes.dex` / `classesN.dex`（可加 `resources.arsc` 作辅证）
  - EPUB：`mimetype` 或 `META-INF/container.xml`（嗅探阶段不读 `file.content`）
  - DOCX：`[Content_Types].xml` + `word/`
- 扩展名增加 `apk` / `apks` / `xapk` / `apkm`，一律同一句安装包文案。
- 本文件不再为嗅探 `import package:archive`。

### 2. 嗅探离开 UI isolate

文件：`lib/services/book_import_coordinator.dart`

- `detectBookImportFormat` 改为 `Isolate.run(...)`（与 EPUB/TXT 解析一致）。
- 主 isolate 只处理 toast / 书架刷新。

### 3. 外部打开/分享：有名字或 MIME 时先拒再拷

文件：`android/app/src/main/kotlin/com/readvibe/app/MainActivity.kt`

- `copyIncomingFile` 在整文件复制前：显示名是 apk 族，或 MIME 为 `application/vnd.android.package-archive`，直接抛中文错误，避免先拷 50MB+。
- 无后缀时仍拷贝，交给 Dart 的中央目录嗅探（已不再整包解码）。

### 4. 测试

文件：`test/book_import_format_test.dart`

- 保留现有无后缀 APK / 有后缀 APK 拒绝用例。
- 增加：带大体积存储条目的 APK ZIP 仍被拒绝（证明不依赖整包 inflate）。
- EPUB / DOCX 无后缀识别保持通过。

## 不做

- 不改 `pubspec.yaml` 版本。
- 不升级 `file_picker`。
- 不把 Android 选择器改回 `FileType.custom`（`mobi`/`azw` 仍会把 MIME 打成 `*/*`）。
- 不为这次 bug 改 USAGE/README。
