# 修复正式 APK 书籍导入失败

当前公开版本是 `0.6.23+69`。按项目规则，落地时只在 `pubspec.yaml` 把版本改为 `0.6.24+70`。

## 问题怎么理解

代码里**没有**把 `.apk` 当书导入的路径。用户说的「使用的时候，导入 apk 会出错」，对应的是：**装上正式包后，书架「导入」失败**。这和调试运行不是同一条路：正式包 `minifyEnabled`、`targetSdk` 走 Flutter 默认（现为 34/35），真机几乎都是 Android 11+。

应用内更新安装 APK（`AppUpdateHandler` / `UpdateDownloadService`）是另一条链路。本次按书架导入修；若实际报错是「安装包包名或版本与更新信息不符 / 签名不一致」，再单开更新安装。

## 导入实际走两条路

```
书架「导入」
  → FilePicker.pickFiles(FileType.custom, allowedExtensions: txt/epub/mobi/azw/azw3/docx/doc/pdf)
  → path + file.name
  → BookImportCoordinator.importFile
  → 各格式解析 → StorageService.saveBook

文件管理器「用 ReadVibe 打开」（ACTION_VIEW）
  → MainActivity 拷到 cache/readvibe_incoming
  → IncomingFileService.consumeNext
  → 同一套 Coordinator
```

解析本身（TXT isolate、EPUB ZIP、PDF 通道、DOC POI）有边界检查，不是「一点导入就崩」的主因。主因在**选文件进不来**，以及**进来后只看文件名**。

## 根因（按可能性）

### 1. Android 11+ 包可见性：点「导入」直接失败（最可能）

`file_picker` 10.3.10 在打开系统文档选择器前会 `resolveActivity()`。本应用 `AndroidManifest.xml` 的 `<queries>` 只声明了 AI/浏览器包，以及 `SEND` / `PROCESS_TEXT` / `TRANSLATE` / `VIEW https`，**没有** `OPEN_DOCUMENT` / `GET_CONTENT`。

`targetSdk >= 30` 时，系统文档 UI 对应用不可见，`resolveActivity` 常返回 null，插件报：

`Can't handle the provided file type.` / `invalid_format_type`

而 `_importBook()` **没有 catch**：

```401:422:lib/screens/library_screen.dart
  Future<void> _importBook() async {
    ...
    final result = await FilePicker.platform.pickFiles(...);
    ...
  } // 只有 finally，没有 catch
```

表现：按钮闪「导入中...」后复原，没有 toast，logcat 里是未捕获 `PlatformException`。这就是「装了 APK 才能复现」。字体导入走同一插件，会一起挂。

### 2. 自定义扩展名在 Android 上等于没过滤，误选 APK 会报格式错误

`file_picker` 的 `getMimeTypes()` 用 `MimeTypeMap`。`mobi` / `azw` / `azw3` 在 AOSP 里几乎没有 MIME；**只要有一个扩展名解析失败，整个过滤器变成 `*/*`**。

列表顺序是 `txt, epub, mobi, ...`，因此真机选择器会列出**所有文件（含 APK）**。Coordinator 只认 `fileName` 后缀：

```41:62:lib/services/book_import_coordinator.dart
      final lowerName = fileName.toLowerCase();
      if (lowerName.endsWith('.epub')) { ... }
      else { throw FormatException('不支持的文件格式，...'); }
```

- 选到 `.apk` → 「不支持的文件格式」
- SAF 的 `DISPLAY_NAME` 经常没后缀（下载器、微信、`msf:123`）→ 同一句，即使正文是 TXT/EPUB
- 不看 `path`，也不看文件头

若用户原话就是「导入 apk 会出错」，这条会直接对上。

### 3. 拷贝失败时 `path == null`，没有字节兜底

选择器拷不到 `cache/file_picker/` 时返回 `unknown_path` 或 `path == null`。界面只提示「无法获取文件路径」，也没设 `withData: true`，云盘/微信内容 URI 很容易走到这里。

### 4. 「打开方式」入口不完整（次要）

- 没有 `ACTION_SEND`，文件管理器「分享到 ReadVibe」无效
- `application/octet-stream` 那条 `pathPattern` 要求 URI 路径带 `.epub` 等；SAF 的 `content://.../document/msf:123` 匹配不上
- Kindle MIME 推断写成 `application/vnd.amazon.ebook → .azw3`，且漏了 `mobi8`；无后缀时会按错格式解析
- 无存储权限；`file://` 在 Android 10+ 常读失败（多数管理器已改 `content://`）

### 5. 错误被吞掉，正式包 PDF/DOC 可能再踩 R8

非 `FormatException` 一律变成「导入失败，请确认文件未损坏后重试」。PDFBox / POI 没有 `-keep`，正式包里 PDF/DOC 可能是混淆问题却看起来像文件损坏。TXT/EPUB/DOCX 是 Dart，不受影响。

章节写入（`4d3bace` 去掉逐章 fsync）不是这次失败点。

## 修改范围

只动导入入口、格式识别、清单 queries 和必要的 R8 规则。不改阅读页排版，不改更新下载。

### A. 让选择器在 Android 11+ 能打开

`android/app/src/main/AndroidManifest.xml` 的 `<queries>` 增加：

- `android.intent.action.OPEN_DOCUMENT` + `CATEGORY_OPENABLE` + `mimeType=*/*`
- `android.intent.action.GET_CONTENT`（插件旧路径/部分 OEM）
- `android.intent.action.CREATE_DOCUMENT`（导出同一套可见性问题，顺手补上，避免修导入、导出再挂）

### B. 书架导入：接住错误 + 不再依赖 MimeTypeMap

`lib/screens/library_screen.dart`（字体选择同一原则，`lib/services/font_service.dart`）：

- `pickFiles` 包一层 try/catch，`PlatformException` 转成可读 toast（选不了文件 / 无法读取 / 已有选择器）
- Android 上用 `FileType.any`（或等价 `*/*`），**在 Dart 里**用路径、文件名、文件头过滤；不要再把 `mobi/azw/azw3` 交给插件 MIME
- `path == null` 时若有 `bytes`，写入应用 cache 再导入
- 传给 Coordinator 的名字优先带真实后缀（`path` 的 extension，其次 `file.name`）

### C. 按路径 + 魔数识别格式，APK 给明确拒绝

`lib/services/book_import_coordinator.dart` 增加纯函数（便于测）：

1. 后缀：`path` 与 `fileName` 都看，`.azw3` 先于 `.azw`
2. 无后缀则读文件头：
   - `%PDF` → PDF
   - `PK\x03\x04` → 再看 ZIP：`mimetype=application/epub+zip` 为 EPUB；`[Content_Types].xml` + `word/` 为 DOCX；含 `AndroidManifest.xml` + `classes*.dex` 为 **APK，明确提示「这是 Android 安装包，不是书籍」**
   - `BOOKMOBI` / Palm header → Kindle
   - 可解码文本 → TXT
3. 仍无法识别 → 现有「不支持的文件格式」文案

`lib/screens/library_screen.dart` 继续展示 `FormatException.message`。

### D. ACTION_VIEW 补强（小改）

`android/app/src/main/kotlin/com/readvibe/app/MainActivity.kt`：

- 修正 MIME→后缀：`vnd.amazon.ebook` → `.azw`；补 `vnd.amazon.mobi8-ebook` / `x-mobi8-ebook` → `.azw3`；补 `vnd.ms-word`
- 无后缀时用拷贝后的文件头补扩展名（与 C 同一套规则，Kotlin 侧做最小魔数即可，细规则仍在 Dart）
- 可选：同样队列处理 `ACTION_SEND` + `EXTRA_STREAM`，清单加对应 `intent-filter`（TXT/EPUB/PDF/Word/octet-stream）

不在此轮扩大到任意二进制「打开即导入」。

### E. 正式包 PDF/DOC

`android/app/proguard-rules.pro` 增加：

- `-keep class com.tom_roush.** { *; }`
- `-keep class org.apache.poi.hwpf.** { *; }`
- 现有 `-dontwarn` 保留

只保导入/解析用到的包，避免 APK 体积失控。

### F. 版本

`pubspec.yaml`：`0.6.23+69` → `0.6.24+70`。

改动用 VS Code 连接的 Android 模拟器直接运行确认即可。

## 不改什么

- 不读、不改任何 `.md`
- 不改阅读页、章节存储 fsync、更新下载线路
- 不把 APK 当书解析
- 不升级 `file_picker` 到 11.x（项目已注明与当前 Kotlin/AGP 不兼容）
