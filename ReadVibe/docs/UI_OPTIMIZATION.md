# ReadVibe v0.1.7 优化记录

本文档回顾 ReadVibe demo 到当前状态为止的主要优化。当前目标已经从“保留 Flutter 全平台模板”收敛为“Android arm64-v8a 优先，Windows 仅占位，其它平台删除”。

## 当前结论

- 正式 demo 目标端：Android arm64-v8a。
- 版本号：v0.1.7。
- 最新本地 APK：dist\ReadVibe-Android-v0.1.7-arm64-v8a.apk。
- iOS、macOS、Linux、Web 平台目录已删除。
- Windows 目录仅保留空壳说明，不参与构建。
- 当前 release APK 约 48.8MB。
- 最近一次完整验证：
  - flutter analyze：通过；
  - flutter build apk --release --split-per-abi --target-platform android-arm64 --build-name 0.1.7 --build-number 8：通过。

## 版本命名规则

- 所有用户可见版本号只允许使用三段式语义版本。
- 禁止在公开版本号后通过加号附加内部构建编号。
- APK 文件名只包含三段式版本和目标 ABI。
- Android 内部 `versionCode` 必须保持递增，但不得写入公开版本号或 APK 文件名。
- 本规则同时记录在项目根目录 `AGENTS.md`，后续发布必须同步遵守。

## 一、基础阅读能力

ReadVibe 的核心定位是本地离线小说阅读器：

- 支持导入 TXT 和 EPUB。
- TXT 支持 UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM、常见 GBK 中文文本，并兼容 CR/LF、NEL、Unicode 行/段落分隔符等换行。
- TXT 会识别常见章节标题，并支持 `# 第1章`、`## 第二章 ##` 及全角 `＃` 标记。
- EPUB 依据 spine 阅读顺序解析章节。
- 章节正文存储在本地应用文档目录，书架元数据、设置和阅读进度存储在平台偏好设置。
- 当前不接入账号、服务器、云同步。

## 二、TXT 排版整理

针对导入 TXT 后排版混乱的问题，已做默认小说排版整理：

- 章节标题删除原文本前导半角/全角空格，避免标题位置不一致。
- 自然段正文删除原文本前导空格后，再统一首行缩进两格。
- 段落之间默认不空行。
- 阅读设置里的顺序固定为“不空行 / 空一行”，也可按需切换为空一行。
- 句号结尾的“第一卷……。/第一节……。”视为正文，不再生成空白伪章节。
- 首个真实章节前的文字会保留为“开篇”，无正文的连续目录项不再成为可跳转章节。
- Markdown 标题先删除 `#` 外壳再检查章节编号，目录与阅读页都不会残留 `#`。
- TXT 解析结果带有解析器版本；打开旧“全文”记录时会自动重建文本、重新分章并写回新目录。

这个策略优先服务小说类 TXT。它不会保留原文件中所有空白格式，因为当前目标是“统一、稳定、易读”的小说阅读排版。

## 三、阅读页交互

阅读页已经从早期的“点击和按钮翻页”改为更适合移动端的逻辑：

- 点击页面只负责呼出/关闭顶部和底部菜单。
- 阅读页使用按下/移动/抬起距离和时长判断短按，正文可选中时也能在第二次点击后可靠关闭菜单。
- 正文选区内部接管双击识别，禁止双击选词，同时保留长按选择、复制、纵向滚动和横向翻章。
- 正文列表永久保持在相同的 `SelectionArea` 层级；菜单开关不再拆卸并重新挂载滚动位置。
- 菜单开关前立即记录当前像素和章节比例，并在下一帧核对控制器位置，防止系统栏变化造成意外跳转。
- 翻章必须左右滑动，避免点击误触。
- 删除章节底部上一章/下一章按钮。
- 阅读页隐藏 Android 顶部状态栏。
- 底部系统手势导航小白条保持可见，不强行覆盖。
- 修复点击呼出菜单时正文轻微下移的问题。
- 修复切换章节时旧章节与新章节短暂重叠、残留的问题。
- 修复新书或单章节书籍无法创建阅读进度的问题。
- 修复章节切换与目录跳转把旧章节偏移写入新章节的问题。
- 修复相邻章节预热导致当前章节意外回到顶部的问题。
- 修复横向拖动取消后页面停留在半途的问题。
- 修复调整字号、行距、字体、页边距或段落间距后正文回到顶部的问题。
- 修复页面卸载时控制器已断开，退出保存用 0 覆盖真实阅读位置的问题。
- 各章节同时保存像素偏移与阅读比例，切章往返和重新打开书籍均可恢复各章位置。
- 上一章和下一章分别使用无进度写入监听的离屏滚动控制器，预热阶段就按保存比例完成定位，不会在拖动露出时先显示章首。
- 翻页提交时读取目标预览页的真实像素和比例，新活动页以同一像素创建；提交前后画面连续，不再出现完成切换后才跳到进度的闪动。

## 四、阅读设置与全局设置

阅读页设置和书架全局设置已统一为同一套字体栏目：

- 系统字体；
- 内置宋体；
- 导入 .ttf / .otf 字体；
- 全局切换字体；
- 阅读页即时切换字体。

阅读设置包含：

- 字号；
- 行距；
- 字重三档；
- 页边距三档，默认中档；
- 段落空行开关；
- 平滑翻页 / 仿书籍翻页；
- 跟随系统、浅色、暖色、深色主题。

设置面板已做紧凑化和可滚动处理，在小屏幕或大字体模式下也不会发生布局溢出。

## 五、主题和沉浸

- 应用支持跟随系统深色/浅色。
- 阅读主题可以手动选择浅色、暖色、深色。
- 书架页和阅读页使用统一的阅读主题色。
- 阅读设置底部面板背景延伸到 Android 底部手势区域，内容仍避开小白条。
- 按钮点击的默认透明水波纹/灰框已尽量移除，避免阅读页出现不需要的透明框反馈。

## 六、翻页模式

### 平滑连续滑动

平滑模式已从简单“切章”改为跟手移动：

- 手指按住页面左右滑动时，当前页跟随手指移动。
- 相邻章节页面会预热并参与布局。
- 相邻页面在离屏预热时同步恢复各章保存位置，第一次露出就是正确进度。
- 滑动过程中可以同时看到当前章节和相邻章节内容。
- 松手后根据滑动距离和速度决定完成翻章或回弹。

### 仿书籍翻页

仿书模式已从简单矩形渐变重做为跟手的曲面翻页：

- 折痕使用三次贝塞尔曲线，不再是一条垂直裁切线；
- 折痕角度跟随手指的纵向落点改变；
- 翻动页包含独立的纸张背面、卷边宽度和淡化透印纹理；
- 当前页、目标页和纸张背面分别使用动态阴影；
- 折页边缘同时绘制暗边、柔光和纸张厚度高光；
- 翻页过程中的目标页按已保存进度露出。

它不是复杂物理引擎，而是适合 demo 阶段的轻量翻书观感。

## 七、打开/关闭书籍动画

最后一轮专门重做了书籍打开和关闭动画。设计参考了 HarmonyOS 官方动效里关于页面间转场、共享元素和“一镜到底”的原则：对象来源要明确，位置和尺寸要连续变化，页面关系不能突兀断开。

当前动画分三段：

1. 点击时截取书架上的原封面画面，并从书架位置放大到阅读页大小；
2. 这一个页面以左边缘为轴，从右向左做 3D 翻开；
3. 页面完全打开后，阅读页接管完整屏幕，随后隐藏 Android 顶部状态栏。

关闭时按同一套逻辑反向执行：

1. 第一时间恢复书架需要的系统状态栏，保证底层书架布局稳定；
2. 阅读页收回为一页，并从左侧合上；
3. 页面回到书架封面位置。

实现要点：

- 动画源点从“整张书卡”修正为“封面图标”；
- 转场优先使用原封面截图，不再额外重绘一本带标题、徽章和书脊纹理的假书；
- 移除旧 Flutter Hero 飞行层，避免和自定义 3D 开书动画叠加冲突；
- 路由使用非 opaque 转场，让关闭时能看到书架背景；
- 转场期间吸收点击，避免动画未结束时误触底层页面；
- 打开时长约 680ms，关闭时长约 520ms，强调精致感而不是盲目加速。

## 八、书架和全局设置

- 书架左上角新增三条横杠菜单按钮。
- 书架页面右滑也可以呼出全局设置。
- 书架设置抽屉使用平滑滑入动效和轻遮罩。
- 书架卡片保留封面、作者/章节/进度信息。
- 长按书籍弹出删除确认。
- 书架页面跟随系统/阅读主题的深浅色。

## 九、性能与数据可靠性

- 书架启动只读取书籍元数据，点击书籍后才按需读取完整正文，降低多书场景的启动 I/O 和内存占用。
- 长章节改为按视口懒加载段落，并使用小型 LRU 缓存复用最近章节的段落拆分结果。
- TXT / EPUB 解析移入后台 isolate，大文件导入不再长时间阻塞 UI。
- 大书章节 JSON 的编码/解码移入后台 isolate，大文件本地读取保护时间由 2 秒调整为 30 秒。
- TXT 使用单换行作为规范段落分隔，是否空一行由显示设置决定，避免 14 MB 级别小说的额外存储膨胀。
- EPUB 归档建立规范化索引，跳过非线性 spine 页面，并限制异常条目数与解压体积。
- 章节文件采用原子替换；应用中断后可从完整的 `.tmp` / `.bak` 自动恢复。
- 设置与阅读进度采用最新写入优先策略，避免较慢的旧异步写入覆盖新状态。
- 旧 TXT 重新分章后，当前进度按全书比例映射到新章节，失效的旧章节偏移不会继续污染阅读位置。
- 横向翻章在拖动开始时锁定离章快照并立即排队保存；切章时先写离章状态，再写目标章节状态，返回上一章时恢复锁定的像素或比例。
- 字体导入增加扩展名、文件大小和文件存在性校验，并去重并发加载、清理替换后的旧文件。
- Android 禁用系统云备份，避免私人书籍正文被自动上传到设备账号。

## 十、APK 体积与平台收敛

为减少 demo 包体积并降低维护范围，已做以下处理：

- Android 只构建 arm64-v8a。
- 删除 32 位 Android 兼容目标。
- 删除 x86/x86_64 模拟器兼容目标。
- release 构建开启 minify 和 shrinkResources。
- 添加 ProGuard 配置。
- 删除 iOS、macOS、Linux、Web 平台目录。
- Windows 只保留占位空壳。

当前推荐构建命令：

~~~powershell
flutter build apk --release --split-per-abi --target-platform android-arm64 --build-name 0.1.7 --build-number 8
~~~
